# 90 天執行計畫與驗收
版本：v0.1｜2026-10-03｜尚未啟動試點

## 起算與執行方式
90 天自試點啟動日算起。先做現場與資源驗證，再以證據決定產品優先順序。
各階段有明確輸出與進入條件；外部依賴未完成時繼續可獨立執行的工作，明列阻塞，不假造合作或成果。

| 階段 | 時間 | 工作 | 輸出與驗收 |
|---|---|---|---|
| P0 現場確認 | 第 1～2 週 | 選地區、訪談機構與家庭、確認合作容量 | 訪談摘要、地區比較、兩個據點與接案責任、同意及退出流程 |
| P1 資源建置 | 第 3～4 週 | 查核 30～50 項資源，整理資格、文件、排除與併領條件 | 每項來源、有效期間、查核人完整；人工案例比對；複雜案件有人工路徑 |
| P2 真實試辦 | 第 5～8 週 | 服務約 20～30 戶，申請／轉介／補件追蹤 | 參與同意、個人行動清單、案件責任人、送件及進度證據；不要求此時全數核准 |
| P3 成果驗證 | 第 9～12 週 | 確認取得、分析停滯、測試更新與續辦提醒 | 彙總成果、匿名案例、成本、錯漏分析、下一階段計畫 |

## 階段進入條件
- P0 → P1：試點地區與需求範圍明確；資料整理可先行，外部窗口未確認則不得宣稱可接案。
- P1 → 真實個案：完成適用資源查核、接案容量確認、權限與資料保存設定；有人負責例外及急迫需求。
- P2 → P3：按實際進度產生成果報告，不等全部案件核准才報告。
- 擴大服務：先確認錯漏原因已處理、轉介容量足夠、成本有經費支持；個案未取得資源也需持續追蹤。

## 執行工作包
| ID | 工作包 | 完成標準 |
|---|---|---|
| STP-001 | 試點地區與機構盤點 | 比較候選地區、列公開窗口、依賴與合作狀態；未聯繫不得標示合作 |
| STP-002 | 資源資料規格與首批目錄 | 30～50 項可查核資源，標記候選／已查核／暫停／過期 |
| STP-003 | 需求問答與資格規則 | 三種初篩狀態、缺漏提示、人工接管、規則版本與案例 |
| STP-004 | 申請陪伴流程 | 行動清單、文件需求、送件方式、補件及結果狀態 |
| STP-005 | 最小產品 | 簡易入口與協助員工作台，支援人工登錄電話／紙本案件 |
| STP-006 | 更新與提醒 | 政策變動、家庭變動、補件、續辦；記錄送達與後續行動 |
| STP-007 | 隱私與權限 | 同意、撤回、存取、保存與刪除、私有個案儲存流程 |
| STP-008 | 真實試點與成效 | 有來源的匿名成果、成本、失敗原因及後續追蹤 |

## 建議角色
負責人決定範圍與預算；資源維護者查核規則；個案協助員負責服務；社工／合作窗口處理專業判斷；工程端完成工具；覆核者驗證資料與成果。
人員可以兼任，但驗收時作者不得自行宣告獨立通過。角色為待配置職責，非已有人到任。

## 首輪驗收目標
- 20～30 戶完成需求盤點。
- 每項正式推薦附有效來源及查核日期。
- 每個已啟動案件都有負責人、下一步及期限。
- 因服務漏追而錯過補件期限：0 件。
- 至少 10 戶新增實際取得幫助；未達標須具體分析。
- 計算服務工時與成本；明列志工投入及贊助，避免把免費投入當成零成本。
- 仍在審查的案件有持續追蹤責任與下一次更新時間。

## 工程驗證
使用合成或匿名測試資料驗證：缺資料、家庭成員口徑差異、政策過期、併領排除、地區不符、通知失敗、撤回同意、無手機使用者及急迫需求。
至少用社工確認的案例檢查漏推薦與錯推薦；示範環境不得連帶提交真實申請。

## 每週報告
本週真實成果、漏斗、未處理期限、資源變更、成本、阻塞、下一週小目標。
分開列：已完成／已驗證／待外部回覆／假設；不得把 prototype 稱為上線服務。

## 啟動後第一個可展示成果
一個獲本人同意並匿名化的完整案例：原先未知資源 → 比對 → 文件 → 送件 → 結果 → 實際取得 → 後續安排。
在真實成果前，合成示範可展示流程，但明確標示非真實個案。

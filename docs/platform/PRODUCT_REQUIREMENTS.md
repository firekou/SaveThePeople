## 1. 終點與產品定位
服務鏈（不可偏離）：
被可信任的窗口接觸 → 說明需求 → 得知可能適用的資源 → 理解資格與缺漏 → 完成申請 → 追蹤補件與審查 → 實際取得幫助 → 持續更新與續辦。

北極星指標：**新增實際取得幫助的家庭數**（定義見 §7）。同時追蹤等待時間、服務工時與成本。

平台定位：
- 是「協助員＋社工＋資源維護者」的共同工作工具，加上給受助者的公開查詢與簡短問答入口。
- 不是核定機關，不做正式資格判定，不代替本人簽署，不假設有政府 API 或線上送件介接。
- 人工服務（電話、紙本、現場）是一級流程，不是例外流程；所有功能都必須能由協助員代為操作。

## 3. 角色定義
| 代碼 | 角色 | 說明 | 帳號 |
|---|---|---|---|
| R1 | 受助者（本人） | 家庭中主要尋求協助者；可為成年家長或照顧者 | 初篩免帳號；持續服務期可選用簡易身分確認（試點後） |
| R2 | 家屬或經確認的代理人 | 經本人授權或依法有代理權者；權限限於授權範圍與期間 | 同 R1，綁定 Consent 中的代理授權 |
| R3 | 個案協助員 | 接案、需求盤點、行動清單、文件與送件陪伴、追蹤 | 內部帳號＋MFA |
| R4 | 社工／專業複核窗口 | 複核初篩、處理裁量與例外、急迫需求、複雜家庭、品質抽查 | 內部帳號＋MFA；可為合作據點社工 |
| R5 | 資源維護與查核人員 | 來源登錄、條件結構化、查核、發布、變動監測 | 內部帳號＋MFA |
| R6 | 資源提供機構窗口 | 回覆轉介受理、名額／容量、服務開始與完成 | 試點初期不給帳號，以電話／Email 由 R3 登錄；試點後可開受限帳號 |
| R7 | 平台管理者 | 帳號、角色、設定、稽核查詢、資料保存與刪除作業 | 內部帳號＋MFA＋雙人覆核敏感操作 |
| R8（輔助） | 成果報告檢視者 | 負責人、資助方會議用；只看匿名彙總 | 內部帳號；無個案存取 |
| R9（輔助） | 獨立覆核者 | 檢查規則、資料與成果；唯讀抽樣，存取需案件層級授權並留稽核 | 內部帳號＋MFA |

規則：
- 一人可兼多角色，但「自己查核的資源版本」不得由自己發布；「自己承辦的案件成果」不得由自己作為品質抽查者驗收。
- R4 的專業判斷記錄在系統中，但正式責任仍依其所屬機構規範。

## 5. 功能清單與分期
每項功能對應服務成果（O1～O7），沒有對應成果的功能不進入規劃。

成果代碼：
- O1 接觸：需要幫助的人經可信任管道進入服務。
- O2 知道：得知可能適用資源並理解條件與缺漏。
- O3 啟動：本人決定申請並備妥文件。
- O4 送達：完成送件或轉介並有收件證據。
- O5 不漏追：補件、審查與轉介回覆被追蹤到結果。
- O6 取得：實際取得幫助並被驗證。
- O7 持續：政策／家庭變動、續辦被處理。
- OQ 品質與成本：錯漏推薦、工時、成本可量測。

## 7. 成果報告定義（統計口徑）
所有報表排除 `is_synthetic = true` 的資料；示範環境與正式環境資料庫分離。

### 7.1 計數單位與去重
- **家庭**：以 Household.household_id 計。同一家庭重複進線時，協助員在建案時以「姓名＋生日＋電話後四碼」等在私有系統內比對，確認後合併（保留合併 AuditEvent）。無法確認者分開計並標記 `possible_duplicate`，報表另列。
- **申請件**：以 Application.application_id 計；同家庭同資源同給付期間只能有一件「進行中」申請（資料庫唯一約束）。
- **資源項次**：同一家庭取得多項資源，家庭只計 1 戶，資源項次另計。
- 家庭若在觀察期內分戶或合併，以首次建案時的 household_id 計，變動另列註記。

### 7.2 階段定義
| 階段 | 計入條件（家庭至少一件符合） | 必要證據 |
|---|---|---|
| 接觸 | 建立 ServiceCase，且有接觸管道紀錄 | 接觸紀錄 |
| 初篩完成 | 有效同意下完成至少 1 次 Assessment（狀態 EVALUATED 或 REVIEWED） | Assessment 紀錄 |
| 啟動申請 | Application 進入 PREPARING_DOCS 以後，且有本人／代理人確認 | 本人確認紀錄 |
| 送件／轉介 | Application 進入 SUBMITTED，或 Referral 進入 SENT 且有對方收件 | 收件憑據（收據、案號、Email 回覆、電話紀錄含對方姓名與時間） |
| 核准 | Application 進入 APPROVED；Referral 進入 ACCEPTED | 核定通知、機構確認或本人告知（標記驗證等級） |
| **實際取得** | Outcome.receipt_status = RECEIVED 或 PARTIALLY_RECEIVED，且 `is_new_to_household = true` | 驗證等級 E1～E3（見下） |

「新增」：建案時記錄家庭目前已使用的資源（baseline_resources）；取得的資源若在建案前 12 個月內已在使用中，不計為新增，另列為「協助續辦」。

取得證據等級：
- E1 本人或代理人口頭／書面確認（記錄日期、金額或服務內容概要）。
- E2 提供機構或承辦人確認。
- E3 文件證據（核定書、物資簽收單等；只記錄已查看，不強制保存影本）。
報表同時呈現各等級數量；不要求銀行明細。

不得計為取得：合成示範、通知已發送、已送件、已核准但尚未給付或服務尚未開始。

### 7.3 轉換率與觀察期間
- 每個轉換率必須寫明：分子、分母、觀察起訖日。例：「試點第 1～90 天完成初篩的 26 戶中，截至第 90 天有 11 戶實際取得（42%）」。
- 主要報告點：試點第 90 天；追蹤報告點：第 180 天（因許多審查超過 30 天，見 [DECISIONS_AND_UNKNOWNS.md](DECISIONS_AND_UNKNOWNS.md) G-03）。
- **審查中**（SUBMITTED／UNDER_REVIEW／SUPPLEMENT_REQUESTED、Referral WAITLISTED）另列，不計成功也不計失敗。
- 撤回、失聯、不核准、額滿各自列數量與原因。

### 7.4 時間、工時與成本
| 指標 | 定義 |
|---|---|
| 首次接觸 → 行動清單 | ServiceCase.created_at 至首份 ActionPlan 交付（列印或傳送）時間，中位數與 P90 |
| 啟動 → 送件 | 本人確認申請至 SUBMITTED |
| 送件 → 結果 | SUBMITTED 至 APPROVED／DENIED |
| 核准 → 取得 | APPROVED 至 Outcome RECEIVED |
| 每戶工時 | Task 與接觸紀錄的工時欄（分鐘），按家庭彙總；含志工 |
| 每戶成本 | （人力工時×費率＋系統月費分攤＋交通等直接支出）÷服務家庭數 |
| 每成功取得家庭成本 | 同上總額 ÷ 新增實際取得家庭數 |

### 7.5 品質
| 指標 | 定義 |
|---|---|
| 錯推薦 | 標示「可能符合」但經 R4 複核或正式結果確認不符合，且原因是資源資料或規則錯誤（不是本人資料變動） |
| 漏推薦 | R4 抽查發現符合條件但系統未列出或列為不符合的資源 |
| 抽查方式 | 每週隨機抽 20% 已完成評估（試點至少 1 案／週），由非承辦的 R4 複核 |
| 停滯原因 | 申請或轉介在同一狀態超過門檻天數（見 [OPERATIONS_AND_PRIVACY.md](OPERATIONS_AND_PRIVACY.md) §2.4）的原因分類 |
| 服務漏追導致逾期 | 補件期限已登錄且責任人未在期限前行動，造成逾期；基線目標 0 件 |

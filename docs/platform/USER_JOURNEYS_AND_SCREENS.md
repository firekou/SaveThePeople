# 使用者旅程與頁面規格
work_id：STP-PLATFORM-PLAN-001｜版本：v0.2-draft｜2026-10-03
角色代碼與權限見 [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md) §3–§4；狀態名稱見 [DATA_MODEL_AND_STATE_MACHINES.md](DATA_MODEL_AND_STATE_MACHINES.md) §3。

## 1. 共同原則
- 每個流程都可由協助員代為操作；畫面上的「本人操作」同時有「協助員代填（電話／現場／紙本）」模式，代填時記錄 `entered_by` 與管道。
- 先問急迫需求；任何一步回答急迫，立即走流程 J5，不必完成問答。
- 資料不足永遠顯示為「資料不足」並說明缺什麼，不顯示為不符合。
- 每個流程的完成證據都寫入 AuditEvent 或對應實體，報表只承認有證據的狀態。

## 2. 服務流程

### J1 自行求助
| 項目 | 內容 |
|---|---|
| 觸發 | 受助者從公開頁、據點海報 QR code、1957 等轉介說明得知平台，自行開啟 |
| 輸入 | 居住縣市／區、需求類別、急迫問題、家庭概況區間（人數、兒少數、收入區間）；不需姓名與身分證字號 |
| 畫面／操作 | 1) 公開首頁「我需要幫忙」→ 2) 急迫問題 3 題 → 3) 簡短問答（P2）→ 4) 候選資源與解釋（P3）→ 5) 「請人協助我」表單：稱呼、偏好聯絡方式、安全聯絡時段、同意聯絡（Consent purpose=CONTACT） |
| 責任人 | 送出聯絡請求前：無（匿名）；送出後：值班協助員（R3） |
| 下一步 | 系統建立 HelpRequest 任務（期限：2 個工作日內首次聯絡，試點前與據點確認）；協助員聯絡後轉 J3 的「本人同意」步驟，建立 ServiceCase |
| 失敗處理 | 未留聯絡方式 → 結果頁提供列印／存檔版與據點電話，不追蹤；聯絡 3 次未接 → 依同意的第二方式；仍失敗 → 標記 HelpRequest UNREACHABLE，保留 30 天後刪除聯絡資料 |
| 完成證據 | HelpRequest 建立紀錄、首次聯絡 Interaction、ServiceCase 建立 |

### J2 合作據點邀請參與
| 項目 | 內容 |
|---|---|
| 觸發 | 據點社工或櫃台在既有服務中判斷家庭可能需要資源導航 |
| 輸入 | 據點、邀請人、家庭是否已口頭同意了解本服務 |
| 畫面／操作 | 1) 據點人員以簡介單（紙本 1 頁）說明服務與資料使用 → 2) 家庭同意後，協助員於工作台「新增案件—據點邀請」→ 3) 當面或電話完成 Consent（purpose=SCREENING, CONTACT）→ 4) 需求問答（協助員代填模式） |
| 責任人 | 邀請：據點人員；建案後：被指派的 R3 |
| 下一步 | 完成初篩 → 行動清單 → J7 |
| 失敗處理 | 家庭不同意 → 不建案，只記錄匿名計數（據點、日期、未參與原因可選填）；據點無協助員量能 → 進入等候清單並告知預計聯絡日（見 [OPERATIONS_AND_PRIVACY.md](OPERATIONS_AND_PRIVACY.md) §2.3） |
| 完成證據 | Consent 紀錄（含簽名或口頭同意紀錄人、時間）、ServiceCase.source_channel=PARTNER_INVITE |

### J3 第三人轉介後取得本人同意
| 項目 | 內容 |
|---|---|
| 觸發 | 學校、醫院社工、鄰里長、親友提出「某家庭可能需要幫助」 |
| 輸入 | 轉介人身分與聯絡方式、被轉介者聯絡方式（僅限轉介人已徵得其同意提供）、轉介理由摘要 |
| 畫面／操作 | 1) 「轉介線索」表單（Referral lead，不是 ServiceCase）→ 2) 協助員聯絡本人，說明誰轉介、為何聯絡、資料怎麼用 → 3) 本人同意 → 建立 ServiceCase 與 Consent；本人拒絕 → 刪除線索個資 |
| 責任人 | R3；轉介人無存取權，最多收到「已聯絡」通知（需本人同意） |
| 下一步 | 同意 → J2 第 4 步之後；需代理人 → J3a 代理授權 |
| 失敗處理 | 7 天內 3 次聯絡失敗 → 回覆轉介人「未能聯絡」（不透露其他資訊）並刪除線索；轉介人未取得本人同意提供聯絡方式 → 不主動聯絡，請轉介人改請本人自行聯絡 |
| 完成證據 | 線索建立與處理結果的 AuditEvent；Consent 紀錄 |

J3a 代理授權：代理人提出時，協助員確認代理依據（本人書面授權、法定代理、監護宣告等），在 Consent 的 `proxy` 區段記錄範圍（查看／修改／代為聯絡／陪同送件）、期間與依據文件類型（只記類型與查看人，不強制保存影本）。正式申請是否可代辦依各方案規定，見 J7。

### J4 沒有手機或不會填表的人工服務
| 項目 | 內容 |
|---|---|
| 觸發 | 受助者來電、臨櫃或據點轉介，表示無智慧型手機、不識字或不會操作 |
| 輸入 | 口述資訊；紙本需求盤點表（與線上問答同題號） |
| 畫面／操作 | 1) 協助員在工作台選「代填模式」，管道=電話／現場／紙本 → 2) 逐題口述，畫面提供「白話唸稿」→ 3) 結果與行動清單以大字版列印或口頭說明，並約定下次聯絡（電話或據點面談）→ 4) 紙本表單掃描不上傳，只登錄結構化答案（減少敏感檔案） |
| 責任人 | R3 |
| 下一步 | 同其他流程；提醒改以電話或據點面談任務進行 |
| 失敗處理 | 聯絡偏好為市話且常不在 → 約定固定時段、改由據點轉達；聽力或語言障礙 → 標記需求，安排家屬陪同或通譯（試點前列可用資源） |
| 完成證據 | Interaction(channel=PHONE/IN_PERSON/PAPER)、列印的行動清單交付紀錄（ActionPlan.delivered_via） |

### J5 急迫需求直接轉人工
| 項目 | 內容 |
|---|---|
| 觸發 | 問答第一頁任一急迫題為「是」：今天或明天沒有食物、即將或已經沒有住處、水電瓦斯被斷、有人身安全疑慮、有人生病無法就醫；或協助員判斷急迫 |
| 輸入 | 急迫類型、所在位置（區）、可聯絡方式 |
| 畫面／操作 | 1) 立即顯示「現在可以撥打」：119／110（生命或人身危險）、113 保護專線（家暴、兒少保護）、1957 福利諮詢專線（號碼為公開資訊，試點前再次查核）→ 2) 若留聯絡方式，建立 URGENT 任務並推送給值班 R3 與 R4 → 3) 同時保存已答部分，事後可繼續中長期問答 |
| 責任人 | 值班 R3（首次回應）＋R4（評估即時資源、必要時依其機構規範處理通報） |
| 下一步 | R4 決定：即時物資／急難救助／轉介；同步建立 ServiceCase 進入一般流程 |
| 失敗處理 | 非上班時段 → 畫面明示「此平台非即時服務」，只顯示公開緊急專線，任務於下個工作日 08:30 優先處理；值班 R3 30 分鐘未認領 → 升級給備援與 R4 |
| 完成證據 | URGENT 任務的認領時間、處置紀錄、結果（已轉介／已提供／無法聯絡） |

注意：涉及兒少保護、家暴等法定通報義務者，依通報人身分與所屬機構規範辦理；平台只提供提醒與紀錄欄位，不代替專業判斷（見 [DECISIONS_AND_UNKNOWNS.md](DECISIONS_AND_UNKNOWNS.md) G-04）。

### J6 資格初篩與人工複核
| 項目 | 內容 |
|---|---|
| 觸發 | 問答完成或協助員在案件中按「重新比對」 |
| 輸入 | Fact（事實）集合及其確認程度；地區；已使用資源 |
| 畫面／操作 | 1) 系統以已發布的 ResourceVersion 與 EligibilityRule 評估 → 2) 每項資源顯示三種結果之一＋逐條理由＋缺漏資料＋人工確認點 → 3) 任何「需人工」條件或矛盾資料自動進入 R4 複核佇列（P5）→ 4) R4 結論：維持／調整並寫理由 |
| 責任人 | 系統計算；R3 解讀；R4 複核 |
| 下一步 | 本人選擇要申請的資源 → 行動清單（P4） |
| 失敗處理 | 規則引擎錯誤 → 顯示「無法自動比對」，該資源標記需人工，不阻斷其他資源；資源版本在評估後被暫停 → 已產生的結果標記 STALE 並建立重評任務 |
| 完成證據 | Assessment（含 resource_version_id、rule_version、輸入快照雜湊、逐條結果） |

### J7 文件準備、送件及補件
| 項目 | 內容 |
|---|---|
| 觸發 | 本人或代理人確認要申請某資源（Application → PREPARING_DOCS） |
| 輸入 | 該資源版本的 DocumentRequirement；家庭已有文件狀態 |
| 畫面／操作 | 1) 文件清單逐項標示：已備妥／需申請（附申請地點）／不適用（需理由）→ 2) 協助員確認申請表內容，本人或代理人逐項確認（在場簽名或電話口頭確認並記錄）→ 3) 依方案方式送件（臨櫃、郵寄、線上、由據點轉交），系統只記錄送件，不自動送出 → 4) 登錄收件憑據 → 5) 收到補件通知 → 建立補件任務，期限依正式通知 |
| 責任人 | 備件：本人＋R3；送件：本人或經授權代理／陪同的 R3；補件追蹤：R3 |
| 下一步 | UNDER_REVIEW 期間每 14 天（或依方案公告審查時程）追蹤一次；結果出來 → J8 或成果紀錄 |
| 失敗處理 | 送件前重複檢查（同家庭同資源同期間已有進行中申請 → 阻擋並顯示既有申請）；補件期限前 5／2 個工作日提醒責任人與本人；期限前 1 日責任人未處理 → 升級備援與 R4 |
| 完成證據 | 本人確認紀錄、收件憑據、補件通知與補件完成紀錄 |

### J8 不核准、撤回、失聯、資源額滿
| 情況 | 觸發 | 操作 | 責任人 | 下一步 | 完成證據 |
|---|---|---|---|---|---|
| 不核准 | 收到不核准通知 | 登錄理由原文摘要；R4 協助理解理由，判斷是否可補件、重新申請或依通知所載救濟管道；同時重評替代資源 | R3＋R4 | 本人決定：申復／替代資源／結束 | Application DENIED＋理由＋本人決定 |
| 撤回 | 本人表示不申請或不想繼續 | 記錄撤回範圍（單一申請／全部服務）；若撤回同意 → 走 Consent 撤回流程 | R3 | 停止相關提醒；依保存政策處理資料 | WITHDRAWN＋本人表示的時間與方式 |
| 失聯 | 依失聯規則（[OPERATIONS_AND_PRIVACY.md](OPERATIONS_AND_PRIVACY.md) §2.4）多次多管道聯絡未果 | ServiceCase 標記 LOST_CONTACT、未送件申請轉 ON_HOLD（皆可恢復）；有期限的申請先通知承辦（若已授權）避免失效 | R3→備援 | 30 天後再嘗試一次；90 天無回應結束服務但保留可恢復 | 聯絡嘗試紀錄 |
| 資源額滿 | 提供機構回覆無名額或公告額滿 | 未送件申請轉 ON_HOLD（原因 CAPACITY_FULL）、轉介轉 WAITLISTED 或 DECLINED；詢問是否候補；推薦替代資源；資源 capacity_status 更新 | R3（案件）＋R5（資源） | 候補 → 定期確認；不候補 → 替代資源 | 機構回覆紀錄 |

### J9 政策變動、家庭變動及續辦
| 情況 | 觸發 | 操作 | 責任人 | 下一步 | 失敗處理 | 完成證據 |
|---|---|---|---|---|---|---|
| 政策變動 | R5 發布新 ResourceVersion（門檻、文件、期限改變）或暫停資源 | 系統列出受影響案件（影響分析，見 [RESOURCE_AND_ELIGIBILITY_ENGINE.md](RESOURCE_AND_ELIGIBILITY_ENGINE.md) §8）→ 為每案建立重評任務 | R5 發布；R3 處理案件 | 重評後若結果改變，通知本人並調整行動清單 | 受影響案件 >20 件 → 依期限排序，R4 協助分流 | 影響清單、每案重評紀錄 |
| 家庭變動 | 本人回報或協助員得知：失業、生育、疾病、搬家、收入變化、成員變動 | 更新 Fact（舊值保留歷史）→ 重新評估 → 新增或結束申請 | R3 | 新的行動清單 | 本人資訊與既有文件矛盾 → R4 複核 | 新 Assessment 與差異 |
| 續辦 | 資源有給付期間或需年度重新申請 | 依 ResourceVersion.renewal_rule 自動在期限前建立續辦任務（例如到期前 45 天） | R3 | 確認仍需要 → J7 | 新年度版本尚未發布 → 任務標記「待資源查核」，同時建立 R5 查核任務 | 續辦 Application 與結果 |

## 3. 頁面規格
頁面代碼 P1～P12。「驗收」為可測試的完成條件；測試情境編號見 [BUILD_PLAN_AND_ACCEPTANCE.md](BUILD_PLAN_AND_ACCEPTANCE.md) §4。

### P1 公開資源查詢
- 目的：讓任何人不登入即可查到已查核資源與其限制。
- 使用者：R1、R2、R3、據點人員、一般大眾。
- 主要欄位：資源名稱、提供機構、層級（中央／地方／民間）、適用地區、需求類別、白話摘要、主要條件摘要、申請方式、窗口、有效期間、申請期限、來源連結、最後查核日期、有效狀態、量能狀態（含 UNKNOWN）。
- 主要操作：依縣市／區、需求類別、關鍵字篩選；查看詳情；列印；「我想知道是否適合我」→ P2。
- 空白狀態：「目前此地區此類別尚無已查核資源」，顯示 1957 與合作據點聯絡方式，不顯示未查核資源。
- 錯誤狀態：資料載入失敗 → 顯示快取版本與其日期；資源已暫停 → 詳情頁顯示「暫停推薦：原因（例如來源失效、查核中）」。
- 權限：公開；只顯示 PUBLISHED 版本；查核人姓名不公開（顯示「查核單位」）。
- 驗收：未發布／暫停／過期資源不出現在列表（T-04）；每筆顯示來源與查核日期；手機 360px 寬度可用。

### P2 簡短需求問答
- 目的：一次說明需求，取得初篩所需最少資訊。
- 使用者：R1、R2 自填；R3 代填。
- 主要欄位：急迫題（3 題）、縣市／區、家庭人數、18 歲以下人數、主要需求類別（多選）、近 3 個月是否有變故（失業、疾病、死亡、離婚、災害）、每月家庭收入區間、是否已有低收／中低收身分（是／否／不知道）、已使用資源（勾選）、偏好聯絡方式。每題都有「不知道／不想回答」。
- 主要操作：上一題／下一題、跳過、儲存草稿（本機或代填時存於案件）、切換大字。
- 空白狀態：首次進入顯示 3 句話說明「需要多久、為何問、資料怎麼用、不是正式審核」。
- 錯誤狀態：輸入格式錯誤即時提示（白話）；網路中斷保留已答內容；急迫題為是 → 直接進 J5。
- 權限：匿名（自填）或指派案件的 R3（代填）。
- 驗收：全部答「不知道」仍能完成並得到「資料不足」結果與缺漏說明（T-01）；題數 ≤15；代填模式記錄管道。

### P3 個人化候選資源與資格解釋
- 目的：讓本人理解哪些資源可能適用、為什麼、還缺什麼。
- 使用者：R1、R2、R3、R4。
- 主要欄位：每項資源：結果（可能符合／資料不足／依現有資料可能不符合）、逐條條件（符合／不符合／未知／需人工）及白話理由、缺漏資料清單、人工確認點、資源版本與查核日期、申請期限、預估負擔（文件數、需不需臨櫃）、排序理由。
- 主要操作：展開條件、選擇「我想申請」、「我有疑問，請人協助」、補答缺漏題、列印。
- 空白狀態：沒有可能符合的資源 → 顯示「目前資料下沒有找到」，列出資料不足項與人工協助入口，不顯示「您不符合任何資源」。
- 錯誤狀態：部分資源比對失敗 → 該資源顯示「需人工確認」；資源在評估後更新 → 顯示「資料已更新，請重新比對」。
- 權限：匿名本次工作階段；案件內依矩陣。
- 驗收：每個結果都有至少一條理由；「可能不符合」結果都標示依據的是自述或已確認資料，且提供複核方式（T-02、T-06）。

### P4 個人行動清單
- 目的：把選定資源轉為具體、有期限的步驟。
- 使用者：R1、R2、R3。
- 主要欄位：步驟（例：「到區公所社會課申請」）、對應資源、需要文件、地點與時間、聯絡窗口、期限、負責人（本人／協助員）、狀態、下次聯絡日。
- 主要操作：勾選完成、改期（需理由）、列印大字版、傳送（依同意管道）、協助員新增步驟。
- 空白狀態：尚未選資源 → 回到 P3。
- 錯誤狀態：傳送失敗 → 顯示失敗原因與改用列印／電話；期限已過 → 標紅並提示協助員。
- 權限：本人與代理人可看與勾選自己的步驟；R3 可編輯。
- 驗收：可產出 A4 一頁大字版；每步都有負責人與期限；無手機情境可完整交付（T-12）。

### P5 文件需求與準備進度
- 目的：讓文件準備可追蹤，不強迫上傳敏感文件。
- 使用者：R1、R2、R3、R4。
- 主要欄位：文件名稱、哪一位成員的文件、是否必要、取得方式（地點、費用、所需時間）、狀態（未準備／準備中／已備妥／已送出／不適用）、是否存放平台（預設否）、到期日（例如診斷書時效）。
- 主要操作：更新狀態、上傳（選用，需 Consent purpose=DOCUMENT_STORAGE）、標記不適用（需理由）、產生取得文件的子任務。
- 空白狀態：資源未設定文件需求 → 提示 R5 補資料，並建立查核任務。
- 錯誤狀態：上傳檔案格式或大小不符；病毒掃描失敗；同意已撤回 → 禁止上傳並提示。
- 權限：依矩陣；檔案下載留 AuditEvent。
- 驗收：未上傳任何檔案也能完成送件流程；上傳檔案在保存期滿或撤回保存同意後自動排程刪除（T-13）。

### P6 申請與服務追蹤
- 目的：每件申請／轉介的目前狀態、下一步、期限與證據一目了然。
- 使用者：R1、R2（唯讀摘要）、R3、R4。
- 主要欄位：資源、版本、申請狀態、轉介狀態、取得狀態（三者分開）、送件日期與方式、收件憑據、承辦窗口、補件期限、下次追蹤日、歷史時間軸。
- 主要操作：狀態轉換（附證據）、登錄補件、登錄結果、登錄取得、撤回。
- 空白狀態：尚未有申請 → 引導至 P3。
- 錯誤狀態：重複申請被阻擋（顯示既有申請）；轉換不合法（例如 DRAFT 直接到 APPROVED）被拒並說明。
- 權限：依矩陣。
- 驗收：重複送件被阻擋（T-10）；核准未取得不計入取得（T-14）。

### P7 協助員案件工作台
- 目的：協助員每天知道要處理哪些案件與期限。
- 使用者：R3（主）、R4。
- 主要欄位：我的案件／備援案件、今日到期任務、逾期、急迫、等待外部回覆、失聯中；每案：家庭代稱、責任人、備援、下一步、期限、最後接觸、下次追蹤日、警示。
- 主要操作：認領、指派／轉移（需理由）、新增接觸紀錄（含工時分鐘）、新增案件（各入口）、批次重排期限（需理由）。
- 空白狀態：「今天沒有到期事項」並顯示下週到期。
- 錯誤狀態：案件無責任人或無下一步 → 系統每日報警並列在管理者頁；同時有人編輯 → 樂觀鎖衝突提示。
- 權限：只看指派或備援案件；R4 看機構案件。
- 驗收：每個進行中案件都有責任人、下一步、期限（資料庫約束＋每日檢查）；逾期任務自動升級（T-15）。

### P8 社工複核佇列
- 目的：集中處理需專業判斷的事項。
- 使用者：R4。
- 主要欄位：複核類型（裁量條件、例外申請、矛盾資料、急迫、品質抽查、AI 草稿審核）、案件、資源、觸發原因、等待時間、優先級。
- 主要操作：認領、查看評估理由、寫結論（維持／調整＋理由）、退回協助員補資料、轉外部專業。
- 空白狀態：顯示本週抽查進度。
- 錯誤狀態：複核時資源版本已變 → 提示重新評估後再複核。
- 權限：R4；複核結論不可由案件承辦 R3 自己做。
- 驗收：所有標記 `requires_human` 的條件都進入佇列（T-08）；結論有理由與時間。

### P9 資源維護、查核與版本管理
- 目的：從候選來源到正式推薦的全程管理。
- 使用者：R5（主）、R4（裁量條件諮詢）、R7。
- 主要欄位：Source（URL、類型、層級、擷取方式、最後抓取、內容雜湊）、Resource、ResourceVersion（全部欄位）、EligibilityRule、查核紀錄（查核方式、聯絡對象、日期、結果）、狀態、下次查核日。
- 主要操作：登錄來源、建立草稿、結構化條件、送查核、查核（查核人≠作者）、發布（發布人≠查核人）、暫停、標記衝突、比較版本差異、查看受影響案件。
- 空白狀態：顯示待查核佇列與到期需重新查核清單。
- 錯誤狀態：缺必填欄位不能送查核；來源 404 → 自動建立查核任務；兩來源衝突 → 不能發布直到解決或標記為需人工。
- 權限：R5 編輯；發布需第二人；R7 可看全部。
- 驗收：未查核的條件無法進入正式推薦（T-04、T-07）；版本差異可顯示；舊評估仍指向舊版本。

### P10 任務、補件、續辦與提醒
- 目的：統一管理有期限的工作與對外提醒。
- 使用者：R3、R4、R5；R1／R2 看給自己的提醒。
- 主要欄位：任務類型、對象、期限、責任人、狀態、來源（補件通知、續辦規則、資源變動、系統檢查）；Notification：通道、內容摘要、送達狀態、失敗原因、改用管道。
- 主要操作：建立、完成、延期（理由）、重新指派、手動補發、改用其他管道、記錄「本人已知悉」。
- 空白狀態：無。
- 錯誤狀態：通知失敗 → 任務標紅並建立「改用其他方式聯絡」子任務（T-11）。
- 權限：依矩陣。
- 驗收：通知「已發送」不會使任務自動完成；需「本人已知悉」或實際行動紀錄。

### P11 機構接案容量與轉介狀態
- 目的：避免轉介到無法接案的機構，追蹤轉介是否被受理。
- 使用者：R3、R4、R5；R6（試點後）。
- 主要欄位：機構、服務、容量狀態（OPEN／LIMITED／FULL／UNKNOWN）、最後確認日期與確認方式、每週可接案數（若有）、轉介清單與狀態、平均回覆時間。
- 主要操作：更新容量（附確認方式）、建立轉介（檢查同意）、登錄回覆、升級未回覆轉介。
- 空白狀態：容量 UNKNOWN → 顯示「需先電話確認」。
- 錯誤狀態：容量確認超過 30 天 → 自動降為 UNKNOWN；轉介 5 個工作日無回覆 → 升級。
- 權限：R6 只看轉介給自己的最小必要資料。
- 驗收：容量 FULL 時建立轉介需確認候補（T-09）。

### P12 成效與成本報表
- 目的：以一致口徑呈現試點成果與成本。
- 使用者：R8、R7、R4；R3 看自身據點。
- 主要欄位：依 [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md) §7 的漏斗（家庭數與申請件數分開）、觀察期間、分母、審查中、各階段時間中位數與 P90、工時、成本、錯漏推薦、停滯原因、撤回／失聯／不核准原因分布。
- 主要操作：選擇期間與據點、匯出匿名彙總（CSV／PDF）。
- 空白狀態：樣本不足（n<5）的格子遮蔽並說明。
- 錯誤狀態：資料不一致（例如取得但無證據）→ 報表頁頂列出資料品質警告，不靜默計入。
- 權限：只輸出彙總；不提供個案下鑽給 R8。
- 驗收：合成資料不進入正式報表（T-16）；每個轉換率顯示分子、分母與期間。

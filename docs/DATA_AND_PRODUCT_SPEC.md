# 資料、資格規則與系統規格
版本：v0.1｜2026-10-03｜待實作設計

## 1. 產品模組
| 模組 | 最小功能 |
|---|---|
| 公開資源目錄 | 地區／需求查詢、有效狀態、來源與查核日期 |
| 需求入口 | 簡短問答、資料不足提示、人工協助選項 |
| 資格初篩 | 版本化規則、逐條理由、候選資源、人工複核 |
| 協助員工作台 | 個案狀態、負責人、任務、補件、結果 |
| 更新與提醒 | 政策變動、家庭更新、期限、送達及失敗處理 |
| 成效報告 | 去重漏斗、取得資源、等待時間、成本與原因 |

初期先支援人工服務，依反覆出現的工作再自動化。技術堆疊、部署平台及訊息服務尚未決定。

## 2. 資源資料
最低欄位：
resource_id、名稱、提供機構、中央／地方／民間、適用地區、需求類別、服務內容、資格條件、例外／排除／併領條件、家庭計算口徑、有效期間、申請期限、文件、申請方式、窗口、來源 URL、來源發布／更新日期、最後查核日期、查核人、版本、有效狀態及量能確認。

每項資格條件記錄所需輸入、資料來源、判斷方法及人工確認點。
不能把不同方案的「家庭成員」或收入／財產計算方式統一為同一套。
額度、年度門檻與地區規則均需版本化，不寫死在模型提示中。
尚未查核的資料可以留在候選庫，不进入正式推薦。

## 3. 個案及申請資料
用私有個案 ID 管理；區分家庭、申請人、資源申請與服務任務。
必要概況按用途漸進收集，記錄自述／文件確認／承辦確認及時間。
同意紀錄涵蓋用途、資料類別、分享對象、提醒、代辦及撤回。
每項申請保存資源版本、比對時間、判斷理由、人工複核、狀態與結果證據。
不假設能取得其他家庭成員資料；需要時另確認適用流程與授權。

## 4. AI 與規則分工
AI：白話解釋、對話引導、候選文件整理、工作摘要與提醒草稿。
規則：依查核來源比對具體門檻、地區、期限與排除條件。
人工：複雜家庭狀況、機構裁量、矛盾資料、例外、急迫需要及正式核定。
模型生成資訊不得直接成为资格规则；每次推荐能回溯来源与版本。
文件擷取結果需確認，不把 OCR／AI 解讀視為權威證明。

## 5. 更新機制
追蹤來源內容變動 → 標記受影響資源 → 人工查核 → 發布新版本 → 重評受影響案件 → 產生必要任務。
來源失效、期限不明或內容衝突時暫停自動推薦。
查核頻率按風險與截止日設定；第一阶段制定频率表，不預設所有來源都有 API 或可爬取。
民間名額与即时物资需另向机构确认，历史网页不代表当前可取得。

## 6. 安全與可用性
- 公開 GitHub 僅存程式、公開資源資料、規格、合成測試及匿名彙總。
- 真實個案、證件、健康／財務資訊、聯絡資訊與憑證不得提交。
- 私有儲存採權限分工、適當加密、存取紀錄、備份及刪除流程。
- 指定資料責任人、保存期間、撤回及事件處理方式；啟用真實資料前確認適用要求。
- 不把敏感原始文件直接交給未確認資料處理條件的外部模型。
- 手機、低頻寬、易讀文字及協助員代為操作一起設計。
- 初篩可不建立帳號；後續持續服務依需要確認身份，避免帳號流程阻斷求助。

## 7. 最小驗證情境
完整資料、缺收入／家庭資料、地區不符、資源過期、來源衝突、額滿、併領排除、不同家庭口徑、人工例外、補件逾期、通知失敗、撤回同意與無手機。
以合成資料驗證權限與資料輸出，確保個案不会进入公开报告。
真实规则测试需保留来源与人工确认记录，不能用模型自生答案当正确基准。

## 8. 啟動前尚待決定
試點地區、合作據點、社工支持、接案容量、預算、個案儲存位置、保存政策、產品堆疊、通知管道及部署方式。
可獨立先做資源盤點、資料規格、合成示範與訪談準備；外部聯繫及真實申請需依負責人的具體安排推進。
